## Learned User Preferences

- Prefer Claude/Raycast-style floating captions: small, minimal, truly translucent glass with no opaque corner chrome, white window chrome, or decorative title bars; the captions window must stay always-on-top when other apps are focused.
- Language controls should be a small disappearing overlay on/above the captions window (not a full-width top bar); the Languages icon toggles translate (From + To) vs same-language transcription, and a small capture/record control stays on the overlay.
- Captions window should be draggable and resizable; resizing must not scale caption text size. Prefer a single idle/hover opacity model with a smooth fade (more transparent when idle, more opaque on hover). The transparency slider must go from solid charcoal through glass to actually clear — do not floor the fill or leave HUD frost on at 0%. New caption turns fade/slide in from above, not down into the clipped bottom edge, so fast lines stay fully readable.
- When asked for approach or design, discuss first and do not start implementing until explicitly told to.
- Prefer Sarvam speech models for English/Indic captioning and translation, especially code-switched speech (e.g. Hinglish, Kannada–English). For international languages, use Gemini Transcribe Live for same-language transcription only; use Gemini Live Translate for translate pairs (Spanish→English, etc.).
- Prefer TypeScript 7 configured consistently across the monorepo.
- When committing agent work, include `AGENTS.md` updates in the same commit (do not leave them unstaged as unrelated).
- Prefer translated-only captions (no source/original under the translation); update progressively in realtime (word-by-word feel) while staying sentence-aware; when the area fills, keep the latest caption visible and prefer continuous sentence flow over fragmented phrases.
- Transcription (translate off) includes Auto detect; Translate To cannot be Auto. Turning translate on from Auto transcription sets To to English.
- Captions start a new overlay line for each provider-finalized speech interval. Pauses below the provider's VAD threshold stay on the same line; once the provider emits `speech_end`, resumed speech starts a new line even while late transcript/translation work settles. Do not concatenate recent turns or deduplicate distinct `utteranceId`s. Gemini Transcribe Live and Live Translate use a 300ms silence window and also soft-split long continuous turns on sentence boundaries (~2.5s+) with a hard max around 5.5s so dense commentary still gets new lines.
- Settings belong in a separate decorated window, not on the captions overlay.
- Keep one palette across the app: the icon's citron (`#d8e48e`) for small accents on charcoal glass (overlay live rule, capture pulse, switch-on), colorful sidebar glyphs in Settings, and warm-white text. Settings is a dark native window (inset grouped lists, segmented controls, chevron rows); do not restyle it as a light web page. Preview backgrounds stay neutral; reserve red for errors and destructive actions. Shared colors live in `apps/desktop/src/tokens.css`.

## Learned Workspace Facts

- Native Doot now owns a private gateway process (ephemeral loopback port + bearer token). Release builds bundle Node, gateway JS, migrations and the Turso addon; debug builds launch repo TypeScript. Native keys belong in Settings Setup and OS credential storage, not `.env`. Standalone browser/gateway development still uses `.env` and its existing repo database; opt into unauthenticated localhost preview explicitly.
- Native history is in the OS app-data directory. Privacy policy controls saving for new sessions and retention; interrupted sessions are recovered/flagged and list queries are summary-only. Do not run standalone gateways against a live native database.
- Capture terminal paths stop the native backend; quit waits for stream finalization before stopping the service. Tests use a fake capture backend and mock providers—do not infer live audio, Windows runtime, or sleep/wake QA from them.
- Settings Connection timing diagnostics keep only 500 in-memory numeric samples/provider labels. They estimate paint opportunities, not physical display latency. `services/gateway/scripts/benchmark-corpus.ts` repeats consented reference clips; reports contain transcripts and belong under ignored `accuracy-local/`. Real accuracy/latency claims require those runs and bilingual review.
- Text-MT diagnostics additionally retain 500 in-memory attempts, including failures/reuse, grouped by language pair and both providers. Gateway `translation_timing` timestamps are session-relative and monotonic; native diagnostics strip session/utterance IDs. Request time includes network round trip. Native Live Translate has no separate text-MT request. Benchmarks report missing translations, request outcomes and revision churn; audio-interval lag remains an estimate.
- Final text requests run with concurrency two and a two-second total budget from eligibility, including queue/draft waits. Completed matching drafts bypass the request slots. Corrected source invalidates obsolete drafts; failed finals never save an old contradictory translation. Stop waits for all finalizations. The pinned route forwards context/name hints and cancellation; Gemini text MT disables thinking. Native sends can catch up with roughly 300 ms chunks when audio is over 250 ms old; Gemini bounds socket backlog and drains before flush. Sarvam stream/VAD defaults stay unchanged pending corpus comparison.

- doot is a macOS- and Windows-first floating live-captions product: system audio → realtime speech/translation → always-on-top overlay.
- Active stack is a monorepo with Tauri 2 + Rust desktop (`apps/desktop`), React + TypeScript + Vite UI, Fastify/TypeScript WebSocket gateway, shared protocol package, and Drizzle + Turso (embedded SQLite) in `@doot/db`. Local runs use bun (`bun run dev`); CI uses npm.
- System audio capture uses ScreenCaptureKit on macOS (Screen Recording permission) and WASAPI shared-mode loopback on Windows; backends push into a shared PCM converter that emits 16 kHz mono S16LE. Global shortcut is `Cmd+Shift+D` (macOS) / `Ctrl+Shift+D` (Windows).
- Speech providers are modular gateway adapters under `services/gateway/src/speech/`; construction is in `server.ts`. Sarvam Realtime STT owns English/Indic live-caption; Sarvam Mayura owns Indic translation.
- Complete routes resolve in `ProviderRouter.resolveRoute` (`services/gateway/src/speech/router.ts`) before speech opens: explicit provider preference order, capability checks, and a pinned text translator. No numeric priorities or automatic mock fallback. `GET /v1/route?source=…&target=…` drives desktop preflight and Settings Connection; `session_started.route` reports the same route. Equal languages (including Auto→Auto) remain transcription on the wire; resolved routes expose explicit mode. Auto detection is scoped to the recognizer. Health coverage excludes mock and requires a complete route. These checks validate configuration, not live credentials/provider uptime.
- Gemini 3.5 Transcribe Live (`GEMINI_API_KEY`) is same-language only (Spanish→Spanish, etc.). International translate pairs (Spanish→English, Auto→Spanish/French/etc.) use Gemini Live Translate (native in-session captions). English/Indic→Indic uses Sarvam Mayura; English/Indic→non-Indic uses Gemini text MT. Auto→English/Indic uses Sarvam. Unsupported pairs emit an unavailable error with blank translated text—never substitute source into translated-only captions.
- Supported live-caption languages are the protocol union of Sarvam Indic + Gemini Live Translate / Transcribe (French/German/Japanese/etc. are valid targets, not just sources). The overlay has no provider toggle.
- Desktop chrome is two windows: captions-only overlay and a decorated Settings window (Doot → Settings… / tray / `open_settings_window`). About lives in Settings (app name and version), not a separate About panel. Doot, Window, and the tray include Show / Hide Overlay (visibility only; does not stop capture). Doot and the tray also include Start/Stop Capturing. The macOS menu extra must open its menu on click — do not `orderFront` the overlay on tray mouse-up, because that dismisses the status item menu before any item can run. Register one global menu handler (the app-wide `on_menu_event`); a second tray handler receives the same click and Show/Hide Overlay hides then immediately shows. Overlay hide uses AppKit `orderOut` so the HUD actually leaves the screen. Overlay prefs use `tauri-plugin-store`; position/size use `tauri-plugin-window-state`.
- Overlay visuals share `apps/desktop/src/tokens.css`; caption chrome lives in `CaptionPanel`. The glass fills the overlay window (no reserved title-bar strip). macOS uses a nonactivating HUD `NSPanel` with HudWindow vibrancy (`NSVisualEffectView` `.behindWindow`, `state = .active`) as a sibling behind an AppKit charcoal dimming layer — never parent captions inside the visual effect view. The transparency slider maps idle opacity 0→1 to clear→opaque fill; HUD frost (`overlayVibrancyAlpha`) peaks in the middle and is hidden at both ends so 100% transparent is actually clear. Do not use `NSGlassEffectView` on the live HUD (it paints the solid inactive look until the overlay is key). Do not stack Tauri `Effect::HudWindow`. CSS `backdrop-filter` is a preview stand-in for browser `web-preview` and the Settings overlay preview and must scale with `--overlay-vibrancy-alpha` so WKWebView does not snapshot the desktop. Windows uses the same fill without CSS snapshot blur and `WS_EX_NOACTIVATE` so overlay clicks do not steal focus. Showing the overlay does not call `set_focus`. A hover-only language chip on the panel holds recent pairs, From/To, the Languages toggle, and capture; Settings and click-through stay off the overlay (menu/tray/shortcut). Utterance lines stack 1:1 with gateway turns; hover-only resize grip; capture pulse while live; language selects lock until stop; listening empty state uses audio bars; errors offer Open Settings. New turns fade/slide in; `prefers-reduced-motion` disables pulse/bars/slide.
- Settings Captions embeds `CaptionPanel` as a live preview with a hover-only language chip ghost, a continuous idle-transparency slider, a text-size slider, and an optional “What's playing?” hint (max 80 characters) sent on the next capture as `start_session.contextHint`. Language From/To live on the overlay, not in Settings. The panel sets `lang` / `dir` from the target language (protocol `od` → HTML `or`); Indic/CJK/RTL use looser metrics than Latin. The Settings window is a dark native layout: searchable sidebar, back/forward toolbar, inset grouped lists, segmented controls, and chevron rows. macOS uses an overlay title bar; Windows keeps a standard decorated title bar and OS-neutral copy (`this computer`, `Ctrl+Shift+D`).
- Settings History lists locally persisted finalized sessions from the gateway (`GET /v1/history/sessions`). Search matches session names, caption text, and language names. Pages hold 20 sessions; capture stop, window focus, and Refresh reload the list. `PATCH /v1/history/sessions/:id` saves names up to 120 characters. Details offer Copy transcript, Text / Subtitles / JSON export, and delete. Live in-progress sessions stay off the list until they stop. The overlay stays captions-only.
- Browser overlay preview adds `web-preview` on `<html>`; Tauri stays fully transparent. Caption/status listeners are skipped in the browser. Preview flags (`/?preview=…`, `/?window=settings`) are ignored in Tauri; starting capture in the browser shows a desktop-app error.
- Settings Connection shows service/selected-language readiness, capture backend, macOS screen-recording permission, Check again, timing diagnostics and an Open system audio settings action. Setup and Connection request Screen Recording with `CGRequestScreenCaptureAccess()` (system prompt); System Settings is only a fallback after TCC has already decided. Windows has no Screen Recording prompt and still opens sound settings. Setup manages native secure keys; standalone gateway development still uses `.env`. Windows Settings copy and shortcut labels stay OS-neutral (`this computer`, `Ctrl+Shift+D`).
- The overlay retains caption lines through reconnects/errors and announces finalized captions separately from visual draft revisions. Status chrome stays quiet unless Starting, No audio detected, Reconnecting, or Finalizing; Listening/Stopped are not a persistent footer. Native `caption://audio` events report PCM RMS activity every 100ms; the meter is not provider VAD. Keyboard focus reveals controls; reduced transparency or increased contrast makes the glass solid. Preferences retain the last translation pair and five recent captured pairs.
- Caption timing is audio-duration-aware: adapters derive speech-start and transcript/end timestamps from PCM interval boundaries. Provider VAD owns utterance boundaries; Gemini Live additionally soft-splits long continuous activities for caption readability. Gateway grace only waits for late events, translation cadence does not define line identity, and only one draft translation runs per turn while the latest source revision is queued. Text MT targets a 1–2s land: first draft is immediate, later revisions use a 40ms trailing / 160ms max-wait, `speech_end` flushes the in-flight draft, drafts abort at 1.4s (skipping Sarvam fallback), and finals abort at 2s. Native Gemini Live Translate never runs that text-MT flush or a source passthrough; late native captions can still attach after `speech_end`. Live Translate cannot take a glossary or system prompt. The gateway infers program/name context asynchronously from recent captions (Gemini Flash when `GEMINI_API_KEY` is set) and applies canonical spellings on new overlay and history lines only — it does not rewrite earlier turns. Blank hint means infer-only; there is no hardcoded show/sport list. Missing Gemini key skips inference so Sarvam-only still works.
- Caption pipeline aims for persistent Sarvam streaming with VAD-driven utterance boundaries and code-switch-tolerant Indic translation (including Kannada).
- Sarvam forwards resumed turns immediately rather than buffering them behind old finals. The gateway keeps up to 32 settling utterances by provider turn ID (or `turnId:speaker` when diarized); a provider-declared pending final gets a bounded 800ms correction window without delaying new drafts. Generic grace remains 350ms. Late first text stays in speech-sequence order in the overlay and cannot steal the live line.
- `collapseStutter` runs on text-MT partials and finals so the translator never sees `go go go`. Consecutive identical tokens cap at two (`no no` stays; `go go go` becomes `go go`); trailing n-grams and unspaced CJK repeats collapse. Native Gemini Live Translate captions skip that filter so emphatic repeats (`Get back Get back`, 待って待って) stay. Overlay identity stays `utteranceId`; optional `speakerId` is metadata. A speaker change settles the previous line; unknown/`UU` does not. Settled diarized lines tint the existing 3px left bar from `tokens.css` (citron / warm white / olive); the live line stays citron. No names or extra chrome. Speechmatics and OpenAI GPT Live Transcribe are explicit STT comparison lanes (`speechmatics`, `openai-transcribe`); translate pairs still use the pinned Sarvam/Gemini text MT, and OpenAI resamples 16 kHz PCM to 24 kHz.
- Completed draft translations remain usable while their source grows by whole words; source corrections still invalidate them, and only the latest draft is queued per turn. Gemini commentary sentence splitting uses ICU Unicode sentence boundaries with a small title/initial guard, including scripts without spaces; VAD/soft-split timing defaults are unchanged.
- `services/gateway/scripts/benchmark-live.ts` returns all turns plus p50/p95 source-to-translation time and estimated final lag. Optional `--reference` JSON contains sourceText and boundariesMs for transcription WER/CER and estimated boundary F1. Provider timestamps are not forced-aligned; synthetic replay tests do not establish live latency or semantic translation accuracy.
- Gateway startup migrates the local Turso SQLite database; it stores one row per successfully opened session, finalized caption segments only, and the session stop time. Draft captions and raw audio stay in memory. Settings History reads that store over HTTP on the local gateway.

## Cursor Cloud specific instructions

Environment: Linux VM with Node 22, npm 10, and Rust 1.83 preinstalled. Docker is NOT preinstalled. The startup update script runs `npm ci`.

- Package manager is **bun** locally. CI (`.github/workflows/ci.yml`) and the gateway `Dockerfile` still use npm. Use `bun run ...` on this machine; cloud/CI use `npm ci` / `npm run ...`.
- Standard commands are in the root `package.json` and README "Useful checks": `npm run typecheck`, `npm run lint`, `npm run test`, `npm run build` all pass on Linux. Only `@doot/gateway` has tests (Node test runner via `tsx`); only `@doot/desktop` has a lint script (eslint). Desktop PCM conversion tests run with `cargo test --manifest-path apps/desktop/src-tauri/Cargo.toml --lib`.
- The **Tauri/Rust desktop app is macOS- and Windows-native** (ScreenCaptureKit / WASAPI). Do not try to run `npm run dev`, `npm run dev:tauri`, or `npm run build:tauri` here — they need the native OS layer and real audio capture. CI `native-check` covers macOS on `macos-latest`; `windows-native-check` covers Windows on `windows-latest`.
- What runs on this VM:
  - Gateway: `npm run dev:gateway` → `ws://127.0.0.1:8787` with `GET /health`. Boots with no API keys.
  - Web UI: `npm run dev:web` → Vite on **`http://localhost:1420`**. It binds IPv6 `localhost`, so `http://127.0.0.1:1420` may fail; use `localhost`. Overlay glass uses a `web-preview` backdrop. Caption chrome: `/?preview=captions`, `/?preview=captions-indic`, `/?preview=listening`, `/?preview=error`. Settings: `/?window=settings` (Captions has a live overlay preview; History talks to the local gateway). Starting capture in the browser shows a desktop-app error; it does not call Tauri.
- No-key end-to-end testing: the gateway has a built-in `mock` speech provider (always `configured`). Open a realtime session with `provider: "mock"` and equal source/target languages (e.g. `en`→`en`) to get full end-to-end captions without any API keys; the translation router is a passthrough when `source === target`. Live captions need `SARVAM_API_KEY` / `GEMINI_API_KEY` in the repo-root `.env` (create via `npm run setup`, which copies `.env.example`).
  - Turso/SQLite is migrated when the gateway starts; `npm run db:migrate` remains available for manual verification. The local file defaults to `packages/db/data/doot.db`; override with `DOOT_DB_PATH`. Docker is not required for the database.
